# Windows에서 한글지 사용하기

## 개요

Windows에서는 별도 프로그램 설치 없이 **Google 일본어 입력**의 커스텀 로마자 테이블을 사용하여 한글지 방식으로 입력합니다. 한자 변환, 후보 선택, 학습 등은 모두 Google 엔진의 기능을 그대로 활용합니다.

코드 제로 — 한글 두 글자만으로 일본어를 입력하세요.

## 설치

### 1단계: Google 일본어 입력 설치

[공식 다운로드 페이지](https://www.google.co.jp/ime/)에서 Google 일본어 입력을 내려받아 설치합니다.

### 2단계: 로마자 테이블 적용

1. 시스템 트레이의 Google 일본어 입력 아이콘을 우클릭 → **속성 (プロパティ)**
2. **일반 (一般)** 탭 → **로마자 테이블 (ローマ字テーブル)** 섹션
3. **편집 (編集)** 버튼 클릭 → 테이블 에디터가 열립니다
4. 에디터의 **編集(편집) 메뉴 → 「ファイルからインポート...」**(파일에서 가져오기)를 선택하고 [`hangulji-romaji-table.txt`](./hangulji-romaji-table.txt)를 선택합니다
   - 가져오기는 기존 항목을 전부 대체하므로 미리 지울 필요가 없습니다
   - `#`로 시작하는 헤더 줄은 가져오기 시 자동으로 무시됩니다
5. **OK** → **적용 (適用)** → **OK**로 저장

### 3단계: 시프트키 설정 변경 (필수)

1. 같은 **속성 (プロパティ)** 창의 **일반 (一般)** 탭에서 **「シフトキーでの入力切替」**(시프트 키로 입력 전환) 항목을 찾습니다
2. 값을 **오프 (オフ)** 로 변경합니다
3. 기본값(ASCII 등)으로 두면 대문자 키 입력 시 임시로 영문 입력 모드로 전환되어, 쌍자음(ㄲㅆㄸㅃㅉ = Shift 키 조합) 입력이 전부 깨지므로 반드시 꺼야 합니다

### 4단계: 입력 모드 설정

- **입력 모드:** ひらがな
- **하드웨어 자판:** 영문 모드
- 한국 2벌식 자판에서 한글 키로 입력합니다

## 사용법

### 기본 입력 흐름

```
xhdnzydn (한글 키로 입력)
  ↓
토우쿄우 (화면에 가나로 표시 — ひらがな 가능 → 로마자 불가)
  ↓
스페이스 누르기
  ↓
東京 (후보 선택)
```

### 입력 규칙

한글지는 가나 철자를 한글로 그대로 적습니다.

- **격음/평음 구분**
  - 격음 ㅋㅌㅍㅊ = 청음(ka ki ku ke ko 등)
  - 평음 ㄱㄷㅂㅈ = 탁음(ga gi gu ge go 등)
  - 예: 카=か, 가=が, 칸=かん, 간=がん

- **장음은 철자 그대로**
  - 토우쿄우=とうきょう, 오오사카=おおさか, 에이가=えいが

- **받침으로 작은 음 표현**
  - ㅅ받침=っ (삿포로=さっぽろ)
  - ㄴ받침=ん (칸=かん, 망가=まんが)

- **한글 자모 덕분에 자동 구분**
  - 칸이(칸+이)=かんい, 카니(카+니)=かに
  - 로마지의 n 모호성 없이 아포스트로피 필요 없음

전체 규칙은 [루트 README](../README.md#입력-규칙)를 참고하세요.

## 한계

### 문자 제약 (정직하게)

일본어에 없는 한글 음절은 **부분적으로만 변환**됩니다. 음절의 몸통(초성×중성)이 매핑 표에 없으면(예: ㅐ 계열) 받침 가능한 자음만 부분 변환되고, 나머지는 입력한 라틴 키 문자가 그대로 화면에 남습니다. 예를 들어:

- 별 (quf) → 화면에 "っuf" (몸통 ㅂ+ㅕ가 매핑 표에 없음)
- 맥 (aor) → 화면에 "んoっ" (몸통 ㅁ+ㅐ가 매핑 표에 없음)

macOS/iOS 버전에서는 한글로 표시되지만, Windows의 Google 일본어 입력은 일본어 음절 한정이므로 이 제약이 있습니다. 오타를 바로 알아챌 수 있다는 장점으로 활용하세요.

### 규칙 변경 시 재설정

표기 규칙이 업데이트되면 새로운 `hangulji-romaji-table.txt`를 다운로드하여 다시 2단계를 반복해야 합니다.

### 실기기 검증 미완

현재 Windows 기기에서의 동작을 완전히 검증하지 못했습니다. **conformance 테스트 2건(픽스처 44케이스 + 받침 재해석 트레이스 6건)이 CI에서 상시 검증**되지만, 실제 Windows 환경에서의 테스트는 아직 미흡합니다. Windows 기기 접근성이 개선되면 검증을 진행할 예정입니다.

문제 발생 시 이슈를 올려주세요.

## 재생성

매핑 규칙을 변경한 후 로마자 테이블을 재생성하려면:

```bash
swift spec/generators/gen-mozc-table.swift
```

생성된 파일은 `windows/hangulji-romaji-table.txt`입니다.

생성기는 실행 시 커버리지 리포트를 출력하며, 현재 `spec/mapping.tsv`의 전 항목이 인코딩됩니다 (인코딩 불가 0건).
